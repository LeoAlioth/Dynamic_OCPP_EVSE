- [ ] **[BUG] Excess margin over-credits — watch-only potential issue** *(surfaced 2026-08-17 during the #41 latch rework; deliberately kept, both err in the chosen stay-on direction)* — (a) **curtailment over-credit**: battery full + export pinned at the limit, an engaged load's draw is folded back into export so the margin reads ~its draw too high; the latch verdict is right (the load eats curtailed energy) but the margin *is* the excess pool, so on a site with **two or more Excess loads** the second sees inflated surplus and can engage without real backing. (b) **discharge not subtracted**: a load pushing the battery from charging into discharging keeps its full draw credited while the discharge counts as 0 ("a discharging battery absorbs nothing"), so it runs on stored energy until falling SOC restores the charge allowance and releases it. Act only on a real-site trigger: a second Excess load engaging without surplus, or an Excess load draining the battery unexpectedly. Fix directions if triggered: per-load pool attribution for (a); a signed battery term for (b) — the latter contradicts the documented absorbs-nothing rule and its tests, so it needs its own design pass.
- [ ] **Off-grid: generator on the grid CT** — an off-grid site may run a backup generator wired through the "grid CT" input. The engine currently equates "has grid CTs" with "grid-tied" (`site.is_off_grid = not has_grid_cts` in `run_hub_calculation`), so a generator-backed site would be treated as having an unlimited utility feed behind the main breaker. Needs a CT/site type setting (grid vs generator): cap the "grid" pool at the generator's rating instead of the main breaker, and disable export-based logic (solar surplus from export, Excess mode) since a generator cannot absorb export.

- [SUPERSEDED — see above] **`excess_margin`: unify the two sinks (refactor)** — `excess_margin` in `calculations/target_calculator.py` branches on `site.is_off_grid` twice, which makes on-grid and off-grid read like two different rules when they are one rule applied to two sinks: _a sink contributes its allowance only while it exists and can absorb_. The grid sink exists when CTs are configured (capacity effectively unlimited, allowance = `excess_export_threshold`); the battery sink exists when configured and can absorb until `battery_soc_full` (allowance = `battery_max_charge_power`). Restructure as a symmetric pair — each sink contributing (currently placed, allowance) and both summed — so the code states that rule and a third sink (second battery, heat store, V2G) becomes an append rather than another branch. Separately, the second `is_off_grid` check (the managed-draw add-back) is not about sinks at all: it exists because `_apply_feedback_loop` already restores managed draws into the grid reading on-grid and returns early off-grid. Behavior-preserving, so `dev/tests/test_excess_margin.py` + the scenario suite are the check. `is_off_grid` stays in the codebase either way (zero grid headroom, feedback-loop skip).
