## Backlog

- [ ] **[BUG] Excess margin over-credits — watch-only potential issue** *(surfaced 2026-08-17 during the #41 latch rework; (b)'s grid-tied half fixed 2026-08-25 by the solar-only export term)* — (a) **curtailment over-credit**: battery full + export pinned at the limit, an engaged load's draw is folded back into export so the margin reads ~its draw too high; the latch verdict is right (the load eats curtailed energy) but the margin *is* the excess pool, so on a site with **two or more Excess loads** the second sees inflated surplus and can engage without real backing. (b) **off-grid discharge over-credit**: off-grid there is no export term for a discharge to be netted against — `_reconstruct_placement` returns export 0 and hands the managed draws back wholesale (the deliberate probe behaviour) — so a load whose draw exceeds the battery's charge allowance keeps the verdict engaged on its own draw while the pack drains, and falling SOC never releases it. Grid-tied this half is closed: `absorbed` now reduces to `production − household` whatever the battery is doing, so a load that pushes the pack into discharge no longer credits itself — except where per-phase clamping on an unbalanced site makes the site-level subtraction inexact. Act only on a real-site trigger: a second Excess load engaging without surplus, or an off-grid Excess load draining the battery. Fix directions if triggered: per-load pool attribution for (a); for (b) an off-grid signed battery term, which contradicts the documented absorbs-nothing/probe rule and its tests, so it needs its own design pass.
- [ ] **Off-grid: generator on the grid CT** — an off-grid site may run a backup generator wired through the "grid CT" input. The engine currently equates "has grid CTs" with "grid-tied" (`site.is_off_grid = not has_grid_cts` in `run_hub_calculation`), so a generator-backed site would be treated as having an unlimited utility feed behind the main breaker. Needs a CT/site type setting (grid vs generator): cap the "grid" pool at the generator's rating instead of the main breaker, and disable export-based logic (solar surplus from export, Excess mode) since a generator cannot absorb export.

- [ ] **[BUG] SOC fan-out is not floor-aware — writing the destination into Deye TOU slots blocks overnight self-consumption** *(observed live 2026-08-25 evening)* — On Deye, the slot SOC the fan-out writes is a **discharge floor + grid-charge target**, not a charging ceiling (verified repeatedly). With the recommendation resting at the destination (no clip), the fan-out holds every managed slot at e.g. 95 all night: the battery (at 92) may not discharge to serve the house → the house runs on grid with 8+ kWh stored (observed: 716 W import, battery idle), and the Deye's grid-charge flag actively imports toward the slot value (throttled only by the charge-limit floor — two controls interlocking). The ceiling intent is already enforced by the charge-rate control (standing destination ceiling, 2026-08-25), so the slot write adds nothing as a ceiling on floor-semantics inverters and is actively harmful outside reservation windows. **Fix direction**: the fan-out writes the slot value only when lowering the floor is the point — the reserve while `reservation_is_due` (the just-in-time drop) — and otherwise restores a configured overnight floor (new optional field, or the value each slot held before Load Juggler's first write; read-before-write + restore needs design) or leaves the slots untouched. Consider a per-inverter semantics setting ("slot register is a floor" vs "true ceiling") since on a genuine-ceiling inverter the current behavior is correct. **Interim**: SOC control switch off + slots set manually to the real overnight floor; the charge limit alone keeps the destination honest.
